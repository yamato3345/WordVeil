# Wordveil server

Звичайний моноліт на Go: один застосунок, один виконуваний файл і спільні
пакети за відповідальністю. Окремих бізнес-модулів немає.

```text
cmd/api/main.go       — точка входу, створення і з'єднання залежностей
internal/
  config/            — конфігурація
  handler/           — HTTP-маршрути, обробники запитів і відповіді
  service/           — бізнес-логіка
  repository/        — запити до бази даних
  model/             — спільні структури даних
  database/          — підключення до PostgreSQL
  cache/             — підключення до Redis
  logger/            — налаштування логування
```

Обробники викликають сервіси, а сервіси звертаються до репозиторіїв.
Залежності створюються у `cmd/api/main.go` і передаються через конструктори.
Нові можливості додаються файлами у відповідних шарах, наприклад
`handler/auth.go`, `service/auth.go` і `repository/user.go`.
Інтерфейси додаються за потреби, а не для кожної структури.

Це початковий каркас: HTTP-сервер, бізнес-логіка і підключення до сховищ
ще не реалізовані. Файли пакетів наразі містять лише оголошення пакетів.

Перевірка збірки:

```sh
go build ./...
go test ./...
```
